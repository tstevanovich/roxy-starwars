# Roxy Kane studio guide

The local studio is the place to compare creative directions, keep original media, finalize reusable assets, and prepare episode scenes for production. Start it with `npm.cmd run dev` from the repository root, then open <http://127.0.0.1:5173>.

Sign in with your owner account before opening records or media. The same saved workspace is available through the phone layout and the private HTTPS tunnel. Read [remote access and account setup](REMOTE-ACCESS.md) for the one-time setup link, startup commands and password recovery. On a phone, the upper-left menu opens navigation; an episode's **Jump to scene** selector avoids long scrolling. Save edits before changing devices because unsaved drafts remain in that browser.

For development commands, TypeScript settings and React examples, see the [TypeScript development guide](TYPESCRIPT.md).

## Manual media generation

Images, videos, dialogue, voice auditions, music and audio repairs start only when the owner presses their Generate or Mix button after reviewing the saved prompt or inputs. Saving, approving, applying a draft, production chat and startup recovery never submit media generation. Existing queued automatic requests are cancelled before submission; already submitted results are retained. There is no episode-wide video hold.

## Produce and download videos by scene

Image requests include an **Images attached to this request** list with ordered thumbnails and **Insert @imageN** buttons. Use those buttons to reference an image inside the sentence that describes its purpose. The **Complete image prompt sent to OpenArt** preview adds the attachment roles automatically, including earlier-shot composition, named character identity, costume, ship, environment and prop references. Character image generation shows the same list and complete preview for each view. Only images within the request's attachment limit receive tags.

Use **Add image reference** to search saved images, **Remove** to exclude a view, and **Earlier / Later** to change attachment order. The counter shows the 16-image limit. **Character sheets only** keeps one sheet for each selected character; **Remove all references** supports a prompt-only request. Inline `@imageN` tags are remapped by the image's identity as the list changes, and removed images' tags become their subject names. The automatic reference instructions are rebuilt from the displayed selection. Review the complete prompt, then **Save image setup** in the shot card before **Generate image**. Character image views save their prompt and selection together with their own Save button. A saved selection is exact, including an empty list; automatic continuity, source or package images are not appended to it. This image selection does not change the video's image/voice attachments.

Production chat uses **propose_shot_image** for an image prompt or reference correction. It creates a shot-specific Apply draft with the complete prompt and ordered attachments, including captured gameplay frames used for composition. Applying changes the active shot prompt and reference list, preserving its timing, dialogue, video directions, sound and sibling shots. An older shot-asset request is routed to the shot selected in the conversation, including a later split part. Empty asset-plan edits are rejected rather than shown as successful drafts. Fractional clip durations such as 6.5 seconds are preserved when saving scene changes; they are not rounded to make an image edit pass validation.

Shots without an explicit reference selection use a compact default: one representative image per linked character/design and the environment view whose title best matches the shot location. Whole character packages and unrelated rooms are not included automatically. Add a portrait for facial detail or a set reference for a specific background when needed; the sheet-only shortcut is optional.

Video prompts use **@Image1** for this shot's approved composition, **@Image2** and subsequent tags for named character identities, and **@Audio1** for the approved dialogue voice reference. End-image selection and automatic links to the next shot's image are retired. The complete prompt preview and submitted request omit old end-image instructions and remap legacy identity tags without changing saved originals. Saving and inserting tags do not generate media.

The episode production board is grouped by scene, with scene shortcuts at the top. Each shot card keeps its image approval, dialogue choices and approved-video download visible even after completion. **Approve dialogue** saves that shot's selected recording immediately. Separate **Image generation prompt** and **Video generation prompt** fields show the complete text used by their respective generators. Edit either field, then use **Save scene** in that section. Saving retains existing files and makes image/video generation explicit for that scene; it does not submit a paid job. **Generate image** requests one new image option. **Generate video** reviews the composition and timed playback together and authorizes one new video, preserving previous takes. Separate storyboard and animatic controls remain under **Detailed reviews and feedback** for corrections.

**Edit this scene** opens the scene's inline title, location and script editor. Each scene has its own save control and recoverable browser draft. Saves compare only that scene's editable inputs, preserve newly generated files and selections, and accept unrelated changes elsewhere in the episode. Conflicting changes to the same scene are rejected without losing the local draft. Image prompt edits affect only that shot's composition review; video prompt edits affect only its timing/video review. Changed dialogue requires a new performance selection. Generation rechecks the exact saved prompt and approved prerequisites before spending credits; repeated requests return their existing job.

After an app update, an older open board displays a reload notice in its production status. Reload the episode once with **Ctrl+F5** to load the new controls. The app's HTML is served without caching.

Shared script, references, shot plan and sound reviews are in **Shared scene preparation**. Each shot is independent: an unreviewed or rendering later shot does not block an earlier shot. The combined action rejects stale inputs, active or uncertain video jobs for that same shot, pending revisions affecting that shot, invalid audio timing. It does not substitute a rendering model.

After picture, performance and sound approval, **Download approved video** downloads that shot's original delivery file directly. Other unfinished scenes and background music do not block it. There is no required CapCut package or episode delivery approval in the board. The older package endpoint remains available for compatibility, but is not part of this workflow. Later edits reopen only the affected content; unchanged approved videos in other scenes remain available for download.

Each scene has **Background music for this section** to prepare, generate, review and download a separate instrumental track sized to that scene's shots. Approved music is reused until its own inputs change. Video dialogue and effects remain in their original soundtracks. Music downloads keep the active project and attachment parameters.

Renderer labels distinguish **Frame-to-video** (the approved image is the literal start frame) from **Reference-to-video** (image and voice references). Current Wan silent shots use frame-to-video; dialogue shots use reference mode, which cannot guarantee a locked background or exact saved-recording lip sync. Text instructions alone do not turn reference mode into frame-to-video. Renderer limitations are explained without imposing an episode-wide generation hold.

Numbered parts now generate independently from their own approved image, exactly like ordinary shots. A following part's image, dialogue or video is never needed for this part. Silent videos use only a literal start frame; dialogue videos keep their approved voice and character identity references. Existing paid takes, selections, approvals and downloads remain available.

Every shot with dialogue automatically includes quoted, speaker-labelled turns, explicit **Lip sync** instructions, Audio 1 voice guidance, and directions for listeners to keep their mouths at rest. This applies to both generated templates and saved custom video prompts; there is no separate Improve lip sync button or opt-in step. The card displays **Lip sync included automatically**, and the visible prompt matches the generation request. For multiple speakers, names are mapped to approved identity reference images; these identities must match characters already in the compositions. Image 2 and later image tags identify characters; they do not supply an end composition. Speech should end naturally rather than stretch to fill the shot. Camera, blocking, sound directions and transition references are retained. Original saved text and selected recordings are preserved. Review the prompt, save any scene edits, then press **Generate video** to request one new take. This follows the dialogue format and explicit lip-sync guidance in [Wan's prompt guide](https://www.alibabacloud.com/help/en/model-studio/wan3-video-generation-prompt-guide). Prompt instructions cannot guarantee exact saved-recording synchronization; the current connector exposes no strict lip-sync switch or general lip-sync repair tool.

Image and video render text excludes recognizable application boilerplate: editing/export notes such as “music is added later in CapCut,” billing and approval status, save/review-before-generation steps, and reminders to measure recordings against the app's limits. **No background music**, visible design, speech, lip sync, camera, action and reference assignments remain generation directions. Voice-library status is excluded from image prompts. Render previews, editable prompt fields and submissions use the same cleanup; stored original prompt text and past job requests remain intact. Dialogue and quoted visible text are protected, including literal editor names when they belong to the story. Production chat keeps workflow instructions in production notes rather than newly written image/video prompts.

Dialogue shots keep Wan reference mode with their own approved shot image, approved character identities and **Audio 1 / voice reference**. Silent shots use only the provider's literal `startFrame`. New requests never send an `endFrame` or the following shot's composition. **Complete video prompt sent to Wan** shows the submitted text and its 4,500-character limit. Save edits and press **Generate video** to request one take. Existing files are retained and no replacement starts automatically.

Dialogue videos include **Character identification** and **Video identity references**. Use **Add video character reference**, **Remove**, **Earlier / Later**, or **Remove all video identity references** to choose the approved character identities used by this shot. These controls are independent of image-generation references. Image 1 stays the approved shot composition and Audio 1 stays the selected dialogue. Up to nine identity images can accompany the composition. Inline identity tags and the automatic cast mapping update with the exact selection and order; removed tags become character names rather than pointing at another attachment. **Save video references** saves the scene without generation. An explicitly empty selection stays empty. Automatic suggestions include approved characters explicitly named in the saved video directions, even if older scene links omit them, plus characters whose identity or package images are selected for this shot's image generation. Non-speaking characters are included, with one canonical identity per character rather than duplicate costume/body attachments. Generated cast blocks and spoken mentions do not establish visible cast. Explicit exclusions such as No Kory and manually saved video selections take precedence; older action fields are consulted only when no custom video directions exist. Reference changes affect this shot's video inputs, not its image setup or sibling shots.

**Sound in this video** shows the editable shot ambience/effects and applicable timed sound-plan cues. Scene-wide cue times are converted to time within the shot; cues for other shots are excluded. These directions are merged into saved custom video prompts as well as default templates. The complete prompt includes sound cues, automatic dialogue/lip-sync directions, character mappings and transition instructions. Saving does not generate media.

Before **Generate image**, each episode shot shows **Images attached to this request**: thumbnails, source names, reference order and roles such as earlier-shot continuity, character identity, ship, set, costume and prop. **View image** opens the actual file, and **Review source shot** opens an earlier shot. Earlier-shot references are identified as saved stills; the previous video and its end frame are not automatically attached. The list uses the same reference selection and 16-image budget as the renderer, and identifies any excluded references. Generation checks that the displayed attachment list is still current. Unsaved scene edits are labelled until saved.

Shot image revisions from production chat update the episode shot's actual `imagePrompt` and selected image references. An image-prompt proposal aimed at an old shot-asset package is routed into a scoped shot-image draft, so applying it changes the prompt shown on the episode card and used by **Generate image**. The draft preview shows that exact prompt. Shot-asset conversations also receive the current episode prompt and reference selection. Image drafts are kept separate for each shot; unrelated scene drafts, sibling shots, recordings and existing takes remain intact. Applying does not generate media.

Each episode shot card has an **Expand shot / Collapse shot** control in its header. The shot title, duration and image/dialogue/video approval indicators remain visible when collapsed. Choices are remembered per shot in this browser; existing prompt and feedback editors stay mounted so folding a card preserves edits. Links to a shot or its detailed reviews reopen that card automatically.

Every shot card has **Discuss this shot**, opening a reusable production conversation for that exact episode, scene and shot in a new tab. Chat displays its focus and **Back to shot** link, reads the latest saved shot, image brief, prompts and selections, and scopes proposed edits to the selected shot. Save local scene edits before discussing them. Opening the conversation sends no message and starts no generation. Existing conversation messages and composer drafts are retained when reopened.

The character **Source evidence** review shows saved gameplay captures with their original timestamps and links back to that moment in the footage. Supplementary public links already saved in source notes or the Creative brief are listed alongside them; displaying a link does not verify its contents or alter an approval. Voice references do not repeat the character's visual source/brief reviews. Their generation panel links to the original character's evidence and shows its saved approval status; voice prompts and audition selection stay independent.

Production chat can **read public webpage links**, including supplementary reference entries, with `read_webpage`. Paste the URL and ask your question; no new connection or API key is needed. It extracts readable HTML/plain text, the title, source URL, links and image URLs, with continuation for long pages. Image URLs and alt text are not visual verification. The reader does not execute JavaScript, log in or bypass blocked sites; chat reports those limitations when encountered. Source content stays separate from owner approvals and generation. It only accesses public internet pages on standard HTTP/HTTPS ports, with validated destinations and redirects, bounded response size and a timeout.

On character and droid reference pages, **Voice and image generation** keeps the prompts and individual Generate controls together. Review or edit **Voice generation prompt**, save it independently, then choose **Generate voice auditions** when ready. You can listen, reject and approve auditions there, or open the linked voice reference. Existing voices are reused by their character link or matching names and aliases; voice prompts are saved separately from the visual asset. A character voice can be prepared before any episode scene uses it. Saving voice directions does not reopen approved character images or generate audio.

Voice direction is resolved consistently for production chat, prompt preview and generation: the linked voice record is authoritative; saved character voice directions are used for older characters without a voice record. Voice-only chat revisions are routed to that voice record and remain pending until applied. Old voice wording in a visual Creative brief does not override those directions. A saved voice direction and a selected audition are separate states. Returning to the character page refreshes saved prompts even if only the voice record changed. Unsaved local prompt edits are labelled and preserved, with **Use saved voice prompt** to load the current saved text. Voice-only changes do not rewrite the visual brief or reopen character image approvals.

New workflow characters and droids receive all nine standard reference entries at creation. Chat image revisions merge item IDs and fields into the existing package; omitting a view from a partial draft does not delete it. Draft previews retain the rest of the package, and the apply path also protects older partial drafts. Removing a reference entry is an explicit action in the asset editor. These record changes never authorize media generation.

A partially prepared character package can use **Add remaining reference views** to add missing prompts and slots while preserving its existing images, directions and approvals. This prepares records only. The Character sheets message links to the actual next step: reference setup when the body-turnaround entry is missing, its Generate controls when no image exists, or its **Approve body turnaround** review once an image is saved. It does not send a production-package character to an empty legacy options area.

Each reference image has its own complete editable prompt, **Save prompt**, **Generate** and review link. Images are generated one at a time, with the master portrait approved before dependent views. Source/brief review remains on the approval board below. If an edited image needs a directions review, **Approve prompt & generate** explicitly records that approval for this image before requesting one take. Saving alone never generates; other image prompts, files and selections are preserved. Prompt drafts stay in this browser until saved.

## Review and finalize creative choices

Open **Creative library** to find Roxy Kane, False Fortune, AL-1B, the recurring pistol, voice records, ship environments, and episode wardrobe. The initial design directions are proposals; nothing is pre-finalized.

1. Open an asset and edit its creative brief or continuity notes.
2. Compare the proposed directions, add another option, or archive an option you no longer want to pursue. Archived options can be restored.
3. Upload local reference files to the appropriate option, or attach files already in the media library.
4. Save changes to MongoDB.
5. Click **Finalize this option** to save the selected direction and its reference snapshot.

A visual asset needs an image or video before it can be finalized. A voice needs an audio audition; its ElevenLabs voice ID and delivery notes can be recorded with the option. Files are imported as local originals, not as remote links.

Saving creative edits to an asset reopens its final choice for review. Changes to asset use, episode assignment, review status, or archive organization preserve approved references, character sheets, and scene approvals. **Decision history** contains up to 30 prior saved versions, including previous final-choice snapshots; each can be downloaded as JSON. Referenced media is retained when an option is archived, detached, or superseded.

## Library organization and review states

Use **Reusable** for recurring characters, droids, props, ships, sets, and voices. Use **Episode only** for wardrobe, locations, props, or staging specific to an episode, and select the episode in the editor. Both new and existing assets support this assignment. The episode scene editor offers reusable assets and assets assigned to that episode; the server rejects links to another episode's assets.

The library has three review states:

- **In development**: the asset is still being prepared. This can be set explicitly while work continues.
- **Pending choice**: options with saved media are ready for a decision, or the asset has been explicitly marked for review. The pending count and status filter collect these items.
- **Finalized**: an option with saved reference media has been approved using **Finalize this option**.

Click **Un-finalize** beside a finalized asset's status to reopen it as **Pending choice**. Its media, options, and previous final choice remain in history. Approving an option again creates a new finalized reference; identity-dependent sheets and scene approvals may need renewed review.

Keep voice auditions and model comparisons inside the main voice asset. **Library organization → Consolidate comparison** copies a comparison's options into the chosen main asset and archives the original record as linked **Comparison history**. If the selected production voice already matches, the completed comparison is retained as archived options. Unresolved new options mark the main asset **Pending choice** while its approved reference remains available until a replacement is selected. Use **Keep current choice** to retain the current option. Consolidation preserves the existing approved reference; transferring a different approved selection from a separate comparison requires finalizing that imported option on the main asset.

**Archive asset** removes a record from current collections while preserving its originals and history. **Archive** lists those records and **Restore asset** brings one back. Organization, archival, and consolidation use revision checks so stale edits cannot overwrite a newer saved record.

## Individual shot images and rejection

Each clip's scene image is reviewed independently in the episode and Creative library. One option contains one image. If a clip has alternatives, each image has its own **Approve image** button, and choosing one does not approve another clip's image. Video generation waits for that clip's exact approved image. The previous Scene 2 multi-image bundle has been split into three clip-specific reviews.

Generator previews use each clip's standalone action, dialogue, camera and sound directions, plus compact names/statuses for the linked references. They do not repeat the full scene script or stale asset-review notes in every shot. The scene script remains available for story review. Wan prompts still show their 4,500-character validation; long shot instructions are flagged rather than truncated. Actual provider submissions require the selected mode's current form and the appropriate approved visual/audio references.

**Reject & delete** permanently removes the studio's stored image, video or audio file and MongoDB media record, removes that choice or take, and clears references from decision history. Other alternatives remain available. Rejecting the current selection also clears its approval/selection and any historical delivery link to that file. This includes ElevenLabs voice auditions and episode dialogue recordings. If that same file is currently approved in another asset or selected in another clip, the server identifies that use and retains the file until that decision is resolved. This is separate from detaching a reference or organizing an asset with Archive. There is no archive step when rejecting a file.

Shot-image reviews, video and dialogue takes, reference attachments (including voice auditions) and the Media library expose the rejection action. Studio copies are deleted; the app does not delete external files originally imported from Downloads or elsewhere, or delete voices/history from the ElevenLabs account. Open drafts retain their text edits while deleted media references are removed, so saving a draft cannot restore a rejected take.

## Character and prop sheets

Every character and droid has a **Character sheets** section in its Creative library editor. Props have a **Prop sheets** section with the same review workflow. After selecting a design, upload or select a saved sheet image, select the views actually visible, and save the sheet. Review the result, then approve it to make it available as a reusable reference. Characters and droids cover front, three-quarter, side, rear, and face detail. Props cover both sides, top, rear, and a detail view, adding front and three-quarter views when useful. Missing views are shown in the editor. Keep episode wardrobe references separate from character identity. All future characters, droids, and props follow this sheet standard.

Sheet registration and approval preserve the finalized identity and record revision history. Pending sheets are excluded from prompt reference IDs and CapCut packages. Approved sheets are included only while they match the same finalized identity; changing or re-finalizing the identity marks earlier sheets as belonging to a previous identity. Saved sheets can be approved while asset edits remain unsaved: approval applies to the saved identity and preserves the local draft. A current draft receives the sheet's updated revision; an older conflicting draft remains recoverable and must be reconciled before saving. Adding a new sheet requires saving asset edits first. Sheet coverage is recorded by the reviewer, not automatically detected from the pixels.

## Local media and durable records

MongoDB database `roxy-starwars` stores asset records, candidates, finalized snapshots, media metadata, series settings, episodes, scene approvals, and revisions. New collections use the `StudioAsset`, `StudioMedia`, `StudioEpisode`, and `StudioSettings` Mongoose models. The existing sample `tasks` collection is left intact.

Original uploaded bytes live in `.data/media`, under generated unique filenames. MongoDB retains the original filename, content type, byte count, SHA-256 checksum, and ZIP checksum. The API returns record-based media URLs rather than exposing filesystem paths. Image, video, and audio previews use local routes with HEAD and byte-range support. Video controls use inline playback, including on mobile browsers.

Supported imports are PNG, JPG/JPEG, WebP, GIF, MP4, WebM, MP3, WAV, M4A, and OGG, up to 250 MB per file. Extension and signature checks reject obvious type mismatches; they are not a full codec validation. Use broadly supported video/audio codecs for playback on your target browser. Each upload is bounded and buffered before saving, so large imports temporarily consume up to the file limit in server memory. A failed metadata write removes only that newly written upload.

Back up **both** the MongoDB data and `.data/media`; record metadata alone cannot reconstruct original files. The automatic development MongoDB stores its files in `.data/mongodb`. Stop it cleanly before making a filesystem copy of those database files, or use MongoDB backup tooling. The entire `.data` directory and local environment files are ignored by Git.

Unsaved editor drafts are retained in the current browser. Saved records and final choices live in MongoDB. Revision checks return a conflict instead of overwriting another tab's saved changes. After a conflict, refresh the workspace to fetch the latest record; **Export draft and reload saved version** downloads the working draft, clears only that editor's browser draft, and loads the latest fetched record in the editor. Clearing browser storage removes unsaved drafts but does not affect saved records or media. An asset can be opened directly with `/?asset=<asset-id>`.

## Plan and approve an episode

The **Episodes** overview shows a short synopsis, production status, target runtime, scene approval counts, and planned clips and selected takes. Choose **Open episode** for the full outline, continuity notes, and scene board. Edit **Episode summary** in that workspace to change the overview synopsis; the full outline is stored separately. Episodes without a summary show only a short excerpt of their outline until a summary is added.

Create an episode in **Episodes**, write its premise, then add scenes. Each scene records its presentation style, location, script, linked library assets, and planned clips. Each clip has an editable duration from 2 to 30 seconds, action, speaker-labelled dialogue, camera direction, and sound effects. The initial duration is just an editable estimate. There is no fixed clip count or ten-second rule.

The workspace totals the planned runtime and vlog/cinematic percentages. Save an episode before approving a scene. Approval records the scene script, planned clip directions and durations, and current revisions of linked creative assets. Editing these inputs marks the saved approval as needing review. Selecting a video take alone does not change the approved script.

**Preview generator prompts** creates separate image and video directions from the current episode draft and linked library records. These are local templates, not AI-written scenes or submitted generation jobs. Video prompts include exact dialogue, effects, and the no-music requirement, and show the Wan prompt-length limit. Review and adapt prompts for the actual mode and references before any provider submission.

Every image and video prompt starts with explicit **Star Wars universe, Imperial era** guidance, including when a clip has no linked assets. Write each clip's action description with that setting and concrete visible details rather than relying on place names alone. The approved ship, character and set references remain authoritative for their designs.

## Take review and CapCut export

Import video takes under their planned clips. The Creative library's **Pending choice** count includes clips with saved video takes and no selected take. **Pending episode video choices** links to the episode workspace, where **Pending video choices** jumps directly to each clip's players. The Episodes overview also marks episodes with pending video choices. Alternate takes on an already selected clip do not create new pending decisions.

**Video takes to review** sits directly below each clip's title and duration, before shot descriptions and the separate dialogue audio players. It shows a player for each attached take. Play it with sound, then click **Approve video take** if accepted. This saves the approved native 1080p selection immediately; save any draft edits first. Failed approvals leave the choice pending. Importing a take alone does not select it. Earlier selected files remain compatible with the **Selected video take** control, whose draft changes still require **Save episode**. Attaching or selecting a take preserves the scene's script approval; changes to scripts, shot directions, or referenced assets still require renewed review. Preserve alternate files in the media library. **Download production brief** exports the saved episode and prompt previews as JSON for review.

Dialogue performances attached to a clip appear under **Dialogue to review**. Compare each recording with the finalized voice, listen for exact words and pronunciation, then click **Use this dialogue** and **Save episode**. **Clear dialogue selection** reopens the performance choice. These episode recordings do not replace reusable voice references. Selected dialogue is included in the CapCut editing package and identified separately in prompt metadata; it is not automatically submitted to a video generator or lip-sync service.

Videos render directly with Wan 3.0 Standard at native 1920 x 1080. Approval saves the selected picture and soundtrack for download and editing. The retired upscale queue, import controls and quality-approval stage have been removed.

Use **Import native 1080p video** for a corrected take made in OpenArt. The server verifies 1920 x 1080 dimensions, an audio track and the planned duration, then saves it as an unselected take for individual review. A failed import keeps the file in the media library and preserves the current selection.

Approval prompts and next-step notices have links to their exact review sections. Following a review link scrolls to, expands and focuses that review, including when opening an episode from Overview. **Needs your attention** on the board provides shortcuts labeled with the scene or clip, dialogue errors linked to the exact dialogue field, and failed or uncertain jobs linked to their details and inputs. Job links expand the job history even when it is collapsed. Blocked reviews link directly to their prerequisite reviews, and proposed revisions have their own anchor links. These links do not approve anything or start generation.

Previously saved high-resolution delivery links remain readable for export. Saving a scene preserves its existing media and selections without creating an upscale request.

**Download CapCut package** becomes available when every scene has current script approval and every clip has a selected video take. The server checks these requirements again. The ZIP contains the selected original video files, media attached to linked finalized assets, and an ordered `manifest.json` mapping scenes and clips to files. It supports packages below 4 GB. Extract the ZIP and import the desired originals into CapCut; this is an editing package, not a native CapCut project file or an assembled episode. Original voice files are included when attached to the linked finalized voice assets.

## Provider integration status

The workspace refreshes saved records when the window regains focus, when it becomes visible, and every 30 seconds while visible. **Refresh workspace** fetches updates immediately. An open editor follows saved updates when it has no unsaved changes. Older episode drafts use their original revision in saved history to merge new media and other nonconflicting updates while retaining local edits. The original draft is backed up in browser storage before the merged draft is persisted. **Save episode** then saves the combined version using the current revision; it does not select pending videos automatically. A save conflict also refreshes the saved record without discarding the draft.

If the same field was edited in both versions, saving pauses and lists the conflicting fields. Choose **Keep my edits in conflicting fields** or **Use saved values in conflicting fields**; unrelated changes are retained either way. Saved pending videos remain viewable during conflict recovery. If the original revision has aged out of the 30-version history, automatic merging is unavailable; **Export draft and reload saved version** preserves a downloaded copy before loading the current record. Asset drafts retain their existing export-and-reload recovery. Newly saved reference sheets remain visible and can be approved even while an older asset draft is open. Sheets awaiting review appear before approved sheets. Approval is disabled while a save is in progress, when a sheet is already approved, or when it belongs to a previous identity.

GPT Image 2.5 Sunburst at 2K/high quality for all images, Wan 3.0 Standard at native 1920 x 1080, 16:9, ElevenLabs voices, and CapCut final assembly are the production choices. Image prompt previews include the shared model/settings policy, and the series settings persist it in MongoDB. [Production chat](PRODUCTION-CHAT.md) can write reviewable story drafts and submit image, video and dialogue jobs after its ChatGPT-plan/OpenArt connections are configured. It imports completed originals as unselected candidates/takes and enforces the script, image and dialogue approval gates. It does not automatically approve generated work or submit media without an explicit generation action. Preserve earlier files and approvals until the user chooses replacements.

## Sound design and finished video review

The production order is: **approve scene script and sound plan -> approve images and dialogue -> explicitly generate one native 1080p video -> review picture, performance and soundtrack -> approve and download**. Separate sound generation and mixing are optional repair tools. Music is reviewed separately for each section.

Each episode scene has a **Sound design** panel. Add continuous ambience and timed effects, describe their sound, choose the applicable clips, set level/trim/timing, and save the episode. A new scene approval includes its sound plan. Previously approved scripts have a separate **Approve sound plan** action, so sound changes do not reopen approved images or dialogue. A changed script or plan requires renewed sound approval before generation or mixing.

Sounds live in Creative library under **Sound effects & ambience**, with reusable and episode-only scope. Link an approved sound, import saved audio, upload a local audio file, or request a new ElevenLabs option. Each option has its own audio player, **Approve this sound**, and **Reject & delete**. New audio is never automatically approved. Generating a replacement marks its sound asset pending choice; approve the replacement or keep the prior option before mixing. Reusing audio and mixing locally spend no generation credits. New ElevenLabs effects display an estimate of 40 credits per generated second; the job records the provider's actual charge when returned. The sound API uses `eleven_text_to_sound_v2`; selected Eleven v3 character voices remain unchanged. See [ElevenLabs sound generation](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert).

After the plan and individual sounds are approved, choose each clip's original video and click **Create sound mix**. The local FFmpeg worker copies the original video stream, retains its synchronized dialogue/audio, mixes approved effects underneath, limits peaks, and saves a separate effects-only WAV stem. Levels, source trim, looping, optional low-pass filtering and timed offsets are explicit in the plan. All-scene looping ambience advances through the scene across clip cuts. Sources that are too short without looping fail visibly. No music is generated or added.

The finished video appears as another unselected take in its clip. Listen and approve that mixed take for direct use in the edit. Mixing does not request an upscale. Changing the approved sound, dialogue selection, source or sound plan makes the prior mix unsuitable for new approval/export. Existing selected stale mixes are flagged for renewed review. Original source files remain available. Delete a derived mixed video before deleting its source or effects stem, which protects retained mixes from dangling file references.

Sound jobs continue on the studio PC after the phone page closes, and their statuses refresh on the scene page.
